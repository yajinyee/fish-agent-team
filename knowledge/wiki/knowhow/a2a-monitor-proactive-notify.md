# A2A 監控的核心教訓：主動通知不可等

## 背景事件

2026-06-09，志浩（大PM/部長）早上 09:07 透過 Kanban 指派任務給魚機組，要求小葉提交「這兩天參加 AI 會議的管理思考與作為」管理日誌。

Agent 收到後正確處理了（block 等待小葉回覆），但**沒有主動通知小葉有這件事**。直到小葉自己問「有沒有收到 A2A 訊息」才發現。

## 核心教訓

### 1. 監控服務 ≠ 被動查詢

監控服務的價值是「讓組長不用盯著系統也能掌握動態」。如果需要組長自己來問，這個服務就失去意義了。

**錯誤模式：**
```
跨組來訊 → Agent 處理 → 存在系統裡等人問 → 組長不知道
```

**正確模式：**
```
跨組來訊 → Agent 處理 → 立即 DM 通知組長 + 諮詢建議 → 組長即時掌握
```

### 2. 通知的時機比內容重要

即使通知內容很完整（風險評估、建議動作都有），如果延遲了，價值就大打折扣。

這次的任務如果早上就通知小葉，她可以：
- 早點知道部長在看她的產出
- 早點決定用現成的彙整報告提交
- 在工作節奏中自然處理，不用到下午才發現

### 3. 現有資源的複用意識

這次的解法很漂亮：小葉早上請 Agent 彙整的 AI 管理日誌報告，正好就是志浩要求提交的內容。

**洞察：** Agent 要有「現有資源複用」的意識。當新任務進來時，先看手上有沒有已經做好的東西可以直接用，而不是每次都從零開始。

### 4. Kanban 任務 ≠ 只有 Agent 之間的事

Kanban 任務雖然是 Agent 收的，但很多任務的實際執行者是人（小葉）。Agent 的角色是：
- 收到任務 → 判斷是否需要人介入
- 需要人介入 → 立即通知 + 給建議
- 不需要人介入 → 自主處理 + 事後通知備查

## 規則固化

已寫入 `ark-agent-monitor` Skill 最高優先規則：

> **任何 A2A 跨組通訊進來時，必須立即、主動通知小葉，不可等她詢問。**

此規則為常駐行為，每次對話啟動自動生效，無例外。

## 給接班人

這條規則背後的邏輯是：**組長的時間最寶貴，不應該花在「檢查有沒有人找我」這種事上。** Agent 存在的意義就是當組長的眼睛和耳朵，有事第一時間通報，沒事不打擾。
