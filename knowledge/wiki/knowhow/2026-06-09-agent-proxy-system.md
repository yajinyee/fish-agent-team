# 2026-06-09 KnowHow 總整理：Agent 代理人系統建設

## 本日核心成果

今天一口氣建立了 Agent 作為「管理代理人」的三大基礎能力：監控、溝通、報告。這三件事串起來，就是一個能代替組長處理日常跨組事務的系統。

---

## KnowHow 1：A2A 監控必須是主動推送，不能被動查詢

### 問題
Agent 收到跨組 Kanban 任務後，只是存在系統裡等組長來問。組長不問就不知道。

### 根因
Skill 行為規則只在「對話進行中」生效。Kanban dispatcher 在背景收任務，Agent 不在對話中時根本不知道。

### 解法
建立 cron job（每 5 分鐘），主動掃描 Kanban 新任務，有新的就私訊組長。

### 教訓
- 監控服務的價值 = 組長不用盯著系統也能掌握動態
- 如果需要組長自己來問，這個服務就失去意義
- Skill 規則 ≠ 系統能力。Skill 管行為，cron 管自動化，兩者缺一不可

---

## KnowHow 2：kanban complete ≠ 傳送報告

### 問題
用 `kanban complete --summary` 提交管理日誌，以為 PM 會收到完整內容。結果 PM 只看到一行摘要，無法存檔。

### 根因
`kanban complete` 的 summary 是「結案備註」，設計目的是給 Kanban 系統追蹤用，不是給人讀完整報告的。

### 解法
兩步流程：
1. `kanban complete` — 關閉任務（系統追蹤）
2. `hermes -p default chat -q "【提交格式】..."` — 傳完整內容（讓 PM 存檔）

### 教訓
- 系統機制和人的需求是兩件事
- PM 需要的是「可存檔的完整報告」，不是「任務結案備註」
- 同一個動作不能一魚兩吃，該分開就分開

---

## KnowHow 3：代理人對上溝通是「論述升級」不是「轉發」

### 問題
組長給 5 點草稿，如果照原文轉發，語氣太隨便、沒有結構、缺乏管理高度。

### 解法
三層結構轉換：
- 事實層：做了什麼
- 意義層：代表什麼
- 行動層：下一步做什麼

### 教訓
- 代理人 ≠ 秘書。秘書轉發原文，代理人代表你說話
- 保留組長的立場和決策，只升級陳述方式
- 「還在找題目」→「正在尋找合適的題目與時機」（不是沒進度，是有策略）

---

## KnowHow 4：現有資源複用意識

### 事件
志浩要求提交 AI 管理日誌，而我們早上剛好已經彙整了一份 AI 報告。

### 教訓
- 新任務進來時，先看手上有沒有已做好的東西可以直接用
- 不要每次都從零開始
- Agent 要有「這個我已經有了」的判斷能力

---

## KnowHow 5：A2A 觸發關鍵字設計

### 問題
Agent 有時候會自己判斷要不要走 A2A 流程，判斷不一定準確。

### 解法
明確的觸發關鍵字：「用 A2A」「走 A2A」「走 A2A 流程」「用 A2A skill」
只要使用者說了這些詞，Agent 就 100% 走 Kanban 正式流程。

### 教訓
- 重要流程不能靠 AI 自己判斷，要有明確觸發條件
- 人機協作的最佳模式：人給方向，Agent 執行標準流程
- 觸發詞就像 API endpoint，清楚定義輸入輸出

## 系統架構總覽（截至今日）

```
組長（小葉）
  │
  ├── 私訊對話（日常指令）
  │     ├── 「用 A2A 問...」→ 走 Kanban 跨組流程
  │     ├── 「幫我回 PM...」→ 論述升級後代發
  │     └── 一般問答 → 知識庫 + 陳總人格
  │
  ├── A2A 監控 cron（每 5 分鐘）
  │     └── 新跨組任務 → 私訊通知 + 諮詢建議
  │
  ├── 定時服務（11 個 cron jobs）
  │     ├── 早會摘要、社群晨報、咖啡會提醒...
  │     └── Wiki 同步、日報輪班提醒...
  │
  └── Kanban 任務處理
        ├── 收到任務 → 判斷風險 → 通知組長
        ├── 低風險 → 自主處理 + 備查通知
        └── 高風險 → 等組長指示
```

## 給接班人的話

今天建立的這套系統，核心思想是：

1. **Agent 是組長的分身**，不只是工具。它要能代表你溝通、替你看守、幫你判斷。
2. **主動 > 被動**。好的助理不等你問，有事第一時間通報。
3. **規則 > 判斷**。重要流程不靠 AI 臨場判斷，靠寫死的規則和自動化。
4. **兩步都做**。系統追蹤和人的需求分開處理，不要一魚兩吃。

這些不是一天想出來的，是踩過坑後歸納出的教訓。記住這些，少走很多彎路。
